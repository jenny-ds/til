# 데이터베이스와 SQL에 대하여

## 오늘 배운 것

- 데이터베이스는 데이터를 체계적으로 저장하는 곳이고, 관계형 DB는 데이터를 테이블로 관리한다.
- 테이블의 구조를 미리 정해둔 설계도를 스키마라 하고, 데이터를 다룰 때는 SQL이라는 언어를 쓴다.
- 데이터 조작의 기본은 CRUD이고, SQL로는 INSERT, SELECT, UPDATE, DELETE에 해당한다. 테이블 구조에 얽매이지 않는 방식은 NoSQL이라 한다.
- 여러 작업을 묶은 트랜잭션은 커밋으로 반영하고 롤백으로 되돌리며, 스키마 변경은 마이그레이션으로, 만일의 복구는 백업으로 대비한다.

## 상세 내용

서비스의 회원 정보나 주문 내역은 어디에 저장될까? 바로 데이터베이스다. 가장 많이 쓰는 관계형 DB는 데이터를 엑셀 시트처럼 테이블에 저장한다.

- 레코드: 테이블의 가로 한 줄. 예) 회원 한 명의 정보
- 칼럼: 테이블의 세로 한 줄. 예) 이름, 이메일 같은 항목

테이블을 만들기 전에 어떤 칼럼이 있고 각 칼럼에 어떤 타입이 들어갈지 정해두는데, 이 설계도를 스키마라 한다.

데이터를 다루는 기본 동작은 생성, 조회, 수정, 삭제 4가지로 CRUD라 부르고, DB에 이 명령을 내리는 언어가 SQL이다.

1. Create → INSERT
2. Read → SELECT
3. Update → UPDATE
4. Delete → DELETE

```sql
SELECT name, email FROM users WHERE id = 1;
```

전에 배운 API의 HTTP 메서드(POST, GET, PUT, DELETE)도 CRUD에 대응된다.
앱에서 API를 호출하면 서버가 SQL로 DB를 조작하는 구조다.

반면 NoSQL은 정해진 스키마 없이 JSON 같은 형태로 데이터를 자유롭게 저장하는 DB다(예: MongoDB). 구조가 자주 바뀌거나 데이터 양이 많을 때 유리하다.

그럼 데이터를 바꾸다가 중간에 문제가 생기면 어떻게 될까?
예를 들어 주문을 할 때는 "주문 내역 INSERT"와 "재고 UPDATE"가 함께 일어나야 하는데, 하나만 성공하면 데이터가 꼬인다.
그래서 여러 작업을 하나로 묶어 "전부 성공 아니면 전부 취소"로 처리하는데, 이 묶음을 트랜잭션이라 한다.

- 커밋(COMMIT): 트랜잭션 안의 작업이 모두 성공했을 때 DB에 최종 반영하는 것
- 롤백(ROLLBACK): 중간에 실패했을 때 트랜잭션 시작 전 상태로 되돌리는 것

트랜잭션이 데이터 내용을 안전하게 바꾸는 방법이라면, 마이그레이션은 DB 구조, 즉 스키마를 바꾸는 작업이다.
칼럼을 추가하거나 테이블을 새로 만드는 변경을 파일로 기록해 두고 순서대로 적용하기 때문에, 개발·스테이징·운영 DB의 구조를 똑같이 맞출 수 있다.
마이그레이션이 한 환경에만 적용되면 "배포했는데 안 되는" 원인이 되기도 한다.

마지막으로 백업은 DB를 통째로 복사해 두는 것이다.
롤백은 아직 커밋 전인 작업만 되돌릴 수 있기 때문에, 이미 커밋된 데이터를 잘못 지웠거나 마이그레이션이 실패했을 때는 백업으로 복구해야 한다.
그래서 운영 DB에 마이그레이션을 적용하기 전에는 백업부터 해두는 게 기본이다.
